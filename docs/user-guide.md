# NEUMA 详细使用与接口参考

本文为当前操作说明，核对日期：2026-10-25；源码基线：`e4f1974`。安装与发布支持范围为 Apple 芯片 Mac；本次核对依据源码、配置和现有测试，没有重新调用真实模型或业务服务。

这里保留完整操作说明、数据规则和开发参考。首次使用请先看 [README](../README.md) 的安装与上手步骤；npm 用户直接在网页设置模型，下面的源码命令供开发者使用。

## 源码版启动

需要 Node.js 22.x 的 22.22.2+、24.x 的 24.15.0+，或 26.0.0+（推荐 26+）；23.x、25.x 不在支持范围内。Pi SDK 固定使用 `@earendil-works/pi-coding-agent@1.0.0`；SDK 为 MIT 开源软件，模型调用费用由所选服务商决定。

```bash
git clone https://github.com/Chriss09-ui/NEUMA.git neuma
cd neuma
npm ci --ignore-scripts
cp .env.example .env
```

模型服务商和模型由用户自行选择。复制配置文件后，在 `.env` 中填写 `NEUMA_LLM_CHAT_URL`（服务商提供的完整接口地址，以 `/chat/completions` 结尾）、`NEUMA_LLM_MODEL`（服务商提供的模型 ID）和 `NEUMA_LLM_API_KEY`（该服务商的 API Key），也可以启动后在网页“设置”中保存这三项。当前支持 OpenAI Chat Completions 兼容接口，模型需支持流式回复和工具调用；其他接口协议需要额外适配，不能仅靠更换模型名接入。

`TYPESAFE_API_KEY` 用于可选的 Jev 需求判断服务，不配置时由需求 Agent 与规则判断。密钥保存在本机，设置接口不会返回完整密钥。

设置的模型服务与 Jev 卡片各有“测试连接”按钮，分别使用当前填写的主模型配置、TypeSafe Key 和 Jev 模型名；API Key 留空时使用各自已保存的 Key，可以先测试再保存。Jev Key 已选择清除时，测试也按清除后的配置处理。测试各发起一次简短请求，显示响应时间或具体错误，最多等待 15 秒，可主动取消；测试不会保存设置，也不会重启进行中的对话。它核实模型请求连通性与 Jev 判断响应格式，主模型的流式回复和工具调用能力仍需在实际使用中验证。

排查 Agent 构建时，可显式调用 `POST /api/settings/test-agent-model`，请求 `{}` 沿用已保存模型。这个独立探针通过真实 Pi 会话验证流式工具调用和工具返回后的后续回复，仅使用一个无副作用工具，不读写 Agent 文件；最多等待 30 秒、使用 512 tokens 测试预算，不修改正式输出设置。返回能力检查和安全错误类别，不返回模型原始正文或凭据。

当前内置配置为小米官方接口上的 `mimo-v2.6-pro` / `mimo-v2.6-flash` 记录了 1,048,576 tokens 上下文与 131,072 tokens 最大输出能力。每次调用仍按具体角色设置较小的输出预算，并受模型上限和实际上下文余量约束；需求整理、架构设计、研发和评审的额度并不相同。预算规则见 [架构说明](../ARCHITECTURE.md)，实现统一在 [model-limits.mts](../src/runtime/model-limits.mts)；未知模型使用保守配置。模型规格参考 [小米官方说明](https://mimo.mi.com/models/zh-CN/mimo-v2.6-pro)。

需求澄清、正式 Agent 与项目助手默认在连续 90 秒没有收到模型响应数据时停止等待，可通过兼容配置项 `NEUMA_LLM_TIMEOUT_MS` 调整（10,000～300,000 毫秒）。每次收到数据都会重新计时，持续返回数据的请求可以累计运行超过 90 秒。无响应停止会保留实际进度，不自动当作成功或盲目重发。

架构设计因无响应停止时，本机失败记录保留等待阶段、最后收包时间与接收量，方便区分一直没有响应和响应途中停顿；这些诊断统计不包含响应正文或凭据。用户主动停止仍记录为取消。

需求兼容接口遇到暂时性网络中断、HTTP 408/429/5xx 时，最多尝试三次（包含首次），遵守服务端 Retry-After；要求等待超过 30 秒时停止，不提前请求。短承接回复已经显示文字后不重放；鉴权、输入、无效 JSON 和协议错误不重试。正式 Pi 调用沿用最多五次自动重连，底层 HTTP 客户端不叠加重试；详见 [架构说明](../ARCHITECTURE.md)。输出截断单独说明，最终失败保留输入和具体类别。若请求已经到达模型但响应在途中丢失，自动重试可能产生额外调用费用。

启动服务：

```bash
npm start
```

打开 [http://127.0.0.1:3000](http://127.0.0.1:3000)。主 Agent 是统一的长期对话与全局管理入口，历史自动保存。左侧“历史对话”可折叠，初次进入时其余空间全部用于聊天，右侧不预先展示工作概览。直接描述想创建的智能体，识别到需求后会展开右侧需求说明；澄清和确认继续使用原来的输入框。点击“创建智能体”或“我的智能体”旁的加号也会在这里开始，无需切换到另一页。“管理项目”保留独立入口，“设置”管理模型连接。

派发或查看具体群任务时，右侧按需展示该群的实际状态、成员分工和成果入口。点击关闭可恢复宽幅聊天，再点击“需求说明”或“群任务”重新展开；关闭面板不清除需求，也不停止群任务。切换历史会话时，草稿和群任务引用跟随各自会话恢复，不能混入另一条对话。

## 刷新后继续查看任务

主对话、智能体制作和研发请求保存成功后，由本机后台继续执行。刷新、切换页面或关闭浏览器不会停止已接受任务；重新打开原对话或智能体即可继续查看已保存的进度。短暂断线会尝试重新连接，不能据此判断任务失败。点击“停止回复”或“终止生成”才发送停止请求；如果请求还在保存，会在取得任务编号后停止。

关闭 NEUMA 后端或关机后，未完成任务按实际记录显示中断；需要继续时沿用原检查点、预算和授权，不会自动重跑。已完成的外部操作不能通过停止撤销。

## 群组与全局管理

点击“我的群组”旁的加号，填写名称、用途并选择成员。成员能力卡展示擅长工作、输入、产出及就绪状态；未就绪成员可以保留在群里，但不能实际认领执行。

在群里发起新任务时，所有就绪成员先判断自己能贡献什么，自主认领并选择本任务的临时整合者。最多两轮协商仍未确定时会停下来说明缺口，你可以点名一位成员整合。工作中成员可定向请求帮助、询问信息，结果返回后继续。右侧任务面板显示分工、执行、等待和结果；点击任务筛选相关消息，选择“新任务”开始另一项工作。首版同群任务排队，不同群可并行，同一 Agent 的多项工作也会排队。

主 Agent 始终在群外，负责了解和管理，不参与群内实际工作。你可以问“哪些任务没完成”“研究组为什么停住”，或要求“把这项工作交给研究组”“把写作 Agent 加入这个群”。主 Agent 默认查看摘要，需要时读取具体记录。群成员只直接唤起本群伙伴，需要群外能力时留下调配请求。

群页可上传共享材料，或明确选择某个 Agent 的私人材料/产物分享给群。主对话也可上传材料并要求主 Agent 转交指定群。材料按目标群复制和登记，入群不会自动共享私人记忆、私聊或原有文件。群成员的文件工具只访问本次群任务子目录；发布成果后，群内保留可查看和下载的文本快照。

群任务在本机服务运行期间可持续执行，切换页面或关闭浏览器不会停止。点击任务的“停止”会停止后续协作并保留已有成果；服务关闭或重启则显示中断，不自动重复文件操作。删除、重建或移出正在工作的成员会中断相关任务，保留结果供重新分配。必需工作未完成时只能明确显示部分交付或待处理，不能冒充全部完成。

归档或恢复群组期间可以切换到其他群；原群操作的迟到回执不会打断当前群的读取、输入或进度同步。

每项任务的执行阶段默认最多 48 个模型逻辑轮次，全局同时最多两个工作成员。额度耗尽会停在待处理状态，可检查成果后创建新任务继续。主 Agent 对话、群任务、消息和成果自动保存；保存失败会显示错误，不把尚未保存的操作当作成功。

## 创建和使用智能体

设计新蓝图时，简单任务直接制定方案；复杂任务会限制每个模块的职责量，并按需扩展模块分工，最多三个模块同时工作。有独立技术难点时，可安排专项子 Agent 提供建议，蓝图负责人确定分工并处理冲突。专项进度保存在本机，耗尽时有对应的恢复入口；建议不代表方案已通过检查。较大的评审任务也会按检查主题、验收条目和历史问题分组，主评审汇总裁决并继续独立范围复核。

蓝图会先检查交互、运行方案和连接协议；模块会检查能力、引用、覆盖和验收，并一次列出可确定的问题。分派前先划分总容量和实际调用额度，避免各模块完成后合并超限。继续旧任务时，已保存成果中的问题会按责任退回，并复核受影响的下游；原稿与用量保留。新提交的蓝图版本绑定由程序维护。必要材料提前提供，最后一次调用用于正式提交；材料不齐且余量不足时在请求前停止。若满足仅缺一次调用的严格条件，可明确授权一次测试续跑，不能重复领取；普通重试不补额度。完整规则见[恢复与例外授权](../ARCHITECTURE.md#46-恢复与例外授权)。

每条需求都要有明确的负责模块，包含不联网、触发方式和数据保存等全局约束。写进全局方案不等于已完成责任分配；遗漏、重复或未知编号会分别指出。仅分工清单有误时，可在原额度内局部补齐并重新检查，保留其余有效设计。

需要返工时，新建的架构修订和研发批次按归属安排独立修复子 Agent；研发即使只有一个跨任务问题，也交给有对应文件权限的修复会话。每组处理少量问题，互不影响的组可同时工作；涉及相同字段或文件的组依次处理。架构补丁须通过业务校验，研发代码补丁须通过文本、文件数量和容量校验，才保存为有效组结果；历史坏结果或合并失败会退回对应组，使用剩余额度继续修正。已受坏基底影响的后续组会保留历史后重新核对，有效兄弟组保留。各组成果和实际用量保存在本机，合并后仍须完整检查和独立验收；具体范围见[架构说明](../ARCHITECTURE.md#45-修订路径)与[研发设计](development-layer-design.md)。

新建的较大研发任务会把接口与任务骨架、用例设计、独立评审分别分派，最多三个分组同时工作；中断后只继续未完成组。开发自测只检查当前和已完成任务，后续任务尚未实现不会提前算失败。缺少代码入口、执行超时或输出超限等明确代码问题会进入原修复额度，环境和权限问题仍如实暂停。额度耗尽或重复参数错误已锁定时，不提供无效的“继续研发”；原记录与用量保留，需先处理阻断。

在主对话中确认需求且通过服务端校验后，系统先把需求保存到该 Agent 的本机文件夹；浏览器收到成功回执后，将它加入左侧“我的智能体”，自动打开并开始设计与检查方案。无需再次手动保存需求或点击生成。轻量助手通过后生成执行定义；需要代码的方案继续研发，界面显示接收设计、拆分任务、开发任务、检查验收、整理交付五个阶段，以及任务通过数量。点击条目或交付卡进入其标准对话界面；可以停止并保存进度、从检查点继续，或重新检查交付。旧版保存的需求或尚未开始制作的入口仍可进入后点击“生成智能体”。模型未配置或构建失败时保留需求，不声称已经生成成功。服务端需求保存失败时不会触发制作，主对话保留已有记录并显示错误，可在排查后重试。

进入尚未就绪的 Agent 时，工作区显示专门的制作界面：需求确认、架构设计、独立评估、按需研发、运行交付。当前阶段的小星核和节点随状态动起来，具体说明跟随后台真实进度；简单方案会明确跳过研发。点击“终止生成”可停止当前架构或研发，刷新后仍能终止后台构建。失败或终止时保留制作界面，显示实际原因，可重新生成或继续研发；通过真实运行检查后才恢复历史对话、产物和任务输入。右上角“智能体设置”和全局导航继续可用，制作面板的“查看需求与方案”可直接打开原需求详情。

桌面对话继续使用原有输入与消息输出，左侧改为可折叠的“历史对话”，只显示当前智能体的记录，按最近更新排序；每行显示首条消息前 30 字生成的标题与时间。点击记录可恢复消息并继续聊天；刷新后打开上次选中的对话，找不到时打开最新一条。顶栏“设置”管理基本资料与记忆，智能体说明留在其中的折叠详情。修改展示名称、简介和头像不改变原始需求或工作指令，无需重新生成。展示名称最多 120 字，简介最多 240 字；清空简介即可恢复无简介。

未设置图标的智能体自动分配一个“小星核”头像，同一个智能体改名或刷新后仍保持原造型与颜色。在“基本资料”中可组合 6 种造型和 8 种配色，预览后点击“保存资料”；“恢复自动分配”可回到默认组合。“文字或 Emoji”中仍可使用原有自定义图标，最多 16 字。侧栏、智能体列表、生成结果和对话页同步展示保存后的头像。鼠标靠近时，外壳轻微转向、圆核跟随；离开后平滑回正。小头像动效幅度更轻，系统启用“减少动态效果”时保持静止。

用户智能体提供**真实对话与工具执行**，复用设置中的模型连接。发送后逐段显示回复，可主动停止；取消、断线或失败保留已收到的文字和实际写入的文件，不伪装完成。输入可继续填写下一条草稿。各 Agent 与主对话、项目助手的会话隔离；“新对话”打开空白聊天，发送首条消息后才加入历史列表。切换历史记录或开启新对话，会停止原任务并保存已收到的内容；迟到回复不会写入新对话。

工作对话自动写入当前 Agent 文件夹，并保留浏览器备份。发送时保存，流式回复每秒合并保存，完成、失败或停止后立即保存；正常保存时顶栏不显示状态文字。保存失败显示“待同步”并可点击重试，刷新后仍保留未同步的新版；多窗口版本冲突会保留本机内容，可另存为新对话。完整历史不限制为最近 80 条，单条记录上限为 8 MiB；超限时显示具体提示并保留当前内容。用于模型下一轮的上下文仍只选当前版本的成功问答，并保留原有长度限制。刷新恢复时未结束的任务标为停止，旧版预览输入不作为已执行任务的上下文。每条历史记录可确认删除；删除当前记录后打开最新剩余记录，没有记录则回到空白聊天。

已就绪助手的输入区可上传、拖入文件，或选择这个助手已经保存的材料；本轮选中的材料以标签显示，发送时关联到当前消息。每个文件最多 20 MiB，每条消息最多关联十个材料；可以只发送附件，也可以补充要如何处理。材料按 Agent 保存，同一 Agent 的不同对话可以再次选择，其他 Agent 无法读取。删除一条历史对话不等于删除其原材料。

上传入口识别 Word（DOC、DOCX、RTF）、Excel（XLS、XLSX、CSV、TSV）、PowerPoint（PPT、PPTX）、PDF、常见文本代码文件，以及 PNG、JPEG、WebP、GIF、TIFF、BMP 图片。文档文本按需提取并分页读取，长内容不会一次性全部塞入模型上下文；只使用实际提取结果，不补造页码、工作表或幻灯片位置。图片与需要视觉读取的 PDF 页面使用支持图片输入的模型。上传完成与读取成功分开显示；损坏、加密、处理失败或模型不支持图片时保留材料及具体原因，不把空结果当作已理解。

发送给模型的图片会转换为 PNG，调整方向并等比缩小至最长边 1600 像素以内，小图不会放大；原文件保留原格式。GIF 只读取首帧，TIFF 可按从 1 开始的页码读取，BMP 当前支持未压缩 24/32 位图像。PDF 页图先按 150 DPI 渲染，再使用同一尺寸限制。超过 4000 万像素的图像会提示处理限制；文档中只处理前 24 张内嵌图片且转换结果总量最多 8 MiB，未处理部分会说明。Word/Excel 图片不保证准确页码或单元格，旧 PPT 不保证精确幻灯片定位。

原件预览与下载使用助手私有保存的原文件。工作目录中另有一份输入副本，专用程序即使改变该副本，也不改变原件或材料工具的读取结果；文件工具会拒绝直接覆盖已登记的输入副本。需要修改材料时，将修改结果另存为产物。

设置中的“记忆”保存当前 Agent 的偏好、背景和工作约定，最多 12,000 字，按 Agent ID 留在服务端，可编辑或清空。保存后下一轮任务生效，正在运行的任务使用启动时的内容；开启新对话或重新生成同一 Agent 的指令仍保留记忆和展示设置。聊天历史与记忆分开，不会自动提炼为长期记忆，模型也不会自行修改。清空记忆不删除已经发生的聊天。

“连接与模型”中，没有未保存修改时刷新会读取最新配置；有草稿时保留输入，其他窗口已更新的配置会触发保存冲突。需要改用服务端最新配置时，点击“放弃修改并刷新”。登录授权初始化期间也可以取消；令牌刷新响应未返回授权范围时保留原范围。完整配置和服务停止行为见 [连接指南](connections-guide.md) 与 [能力和运行说明](agent-capabilities-and-services.md)。

点击“让 NEUMA 帮我迭代”，回到对应需求说明；确认修改后更新同一入口，并重新生成工作指令。新版本使用新执行上下文，不自动继承旧指令的任务历史。相同需求且当前架构版本与已使用能力兼容时，可复用经过评估的定义；新增公共材料工具不要求重写已就绪助手的指令或重新研发。旧原型已停止运行，显示需要重新设计与检查；重新生成并通过后才能使用。旧需求、记忆、展示资料与文件保留，不会自动改写或删除。方案与检查结果可在设置的原需求区域展开查看。架构未通过、待连接或需要研发时，不解锁新版执行。

每个 Agent 使用独立的 `.neuma/agents/<id>/` 文件夹，按稳定 ID 保存；修改展示名称不会移动目录。定义、指令、记忆、展示设置、需求、架构、研发代码与记录、只读交付快照、历史对话和运行产物都在其中。原始 `name` 和 `draft` 用于构建，展示名称、简介和头像单独保存在 `profile`，修改展示设置不改变构建版本。正式助手共享材料读取工具，业务工具按评估方案提供；文件工具仅操作该 Agent 的 `workspace/`，材料工具只读取该 Agent 的材料，不能读写同文件夹内的定义、记忆、对话或研发元数据，也不能访问其他 Agent。同一 Agent 的上传材料可在不同对话中再次选择使用，发送时明确关联本轮材料。删除助手会停止相应任务、移除定义与活动元数据及保存对话，留下删除标记，保留代码、快照和运行产物。重启服务或清除浏览器数据后，可从服务端恢复未删除的 Agent 入口和历史对话。

右上角“产物 · 数量”可查看当前 Agent 的全部文件。弹窗左侧显示文件列表和刷新按钮，右侧显示预览、文件说明及下载；首次打开选择最近更新的文件，再次打开保留上次选择。进入 Agent 或任务结束后自动刷新，也可在弹窗手动刷新；切换文件直接更新同一个弹窗，关闭或按 Esc 后焦点回到“产物”按钮。切换 Agent 会关闭弹窗，各 Agent 的文件列表独立。回复中的文件名不代表文件已保存。支持不超过 20 MiB 的文本文件，与上传材料和隔离程序运行文件的上限一致；预览最多显示 120,000 字，常见凭据值会隐藏。HTML 使用隔离的静态预览，不执行脚本、加载外部资源或取得宿主权限。内容过长时只显示部分并提示，不把截断内容作为完整文件下载。

架构接口、状态与限制见 [架构说明](../ARCHITECTURE.md)。设计和评估分别使用独立模型会话；需要时额外检索固定官方技术目录或委派最多三个模块顾问，顾问不能递归委派。检索目前覆盖 Node.js、Pi、LangChain、LangGraph，非通用全网搜索，不需要新密钥。模型继续使用已配置服务商，不新增分析或遥测。修订与恢复受对应阶段的预算和显式授权约束，失败不会自动通过；用户 Agent 运行仍可主动取消，临时网络问题沿用 Pi 的有限重连机制。

主对话在服务端自动保存消息、需求草稿和实际失败状态，可从“历史对话”恢复；它与各工作 Agent 的历史分别保存。旧独立创建页面的手动快照按钮已退出当前入口，旧数据迁移见下节，无需依靠这些按钮保存当前需求。

服务器只监听本机地址。调用模型时，会发送当前请求、按任务选择的历史、需求草稿、相关证据或工具结果；启用 Jev 且本轮匹配到回答点时，会把该项要求和相关用户原话发送给 Jev 辅助判断。需求处理中的最近用户原话摘要最多 12 条、共 12,000 字，这不是整份会话的存储上限，也不代表所有模型输入的总上限。服务方的数据处理以其各自政策为准。

## Agent 文件夹与旧数据迁移

源码版默认目录在本项目下的 `.neuma/agents/<Agent ID>/`；npm 命令行版默认使用用户主目录下的 `.neuma/agents/<Agent ID>/`：

```text
definition.json                 定义、工作指令、记忆、展示设置
requirements.json               已保存需求
architecture.json               本 Agent 的全部架构版本
conversations/records/<id>.json  独立的完整历史对话；删除后同文件只留标记
development/records/            研发检查点和交付记录
development/workspaces/         按研发批次划分的代码
development/snapshots/          内容摘要命名的只读快照
workspace/                      输入材料和任务产物
workspace/inputs/<材料 ID>/       上传材料的独立工作副本，使用安全文件名
attachments/<材料 ID>/           私有材料元数据与解析缓存
attachments/<材料 ID>/original/  私有权威原件；解析、原件预览与下载的来源
pi/                             本 Agent 的 SDK 辅助目录（按需）
```

升级后首次启动会统一检查旧 `agents.json`、`architectures.json`、研发记录和目录，再复制到新布局；重定位快照路径，不改变代码摘要、候选哈希、稳定 ID、记忆或修复预算。全部复制成功后才发布 Agent 目录和迁移标记；迁移失败保留旧文件，修正后可重试。旧文件作为迁移前备份保留，完成后不再读取它们作为活动数据；不要让旧版本与新版本服务同时写同一数据目录。

服务启动时将旧 `conversations/saved.json` 的手动快照迁为一条 `legacy-saved` 历史对话。页面首次连接会把旧浏览器里的需求与手动保存对话按 Agent 导入文件夹；普通旧快照补入 `legacy-saved`，尚未同步成功的不同内容单独补入 `legacy-browser-pending`，与磁盘旧对话并存。已有新格式服务端记录优先，确认迁移成功后才清除浏览器旧单份键；迁移可重复执行，不产生重复记录。从旧定义或架构推导的需求允许补入更新的旧浏览器版本。对话与 Agent 的删除标记都会阻止旧备份复活。NEUMA 共用的模型设置和“管理项目”数据仍独立保存，不复制密钥到各 Agent 文件夹。

接口：`GET /api/agent-requirements` 返回需求入口；`POST /api/agents/:id/requirements` 保存需求。`GET /api/agents/:id/conversations` 返回历史摘要；`GET/POST /api/agents/:id/conversations/:conversationId` 读取或保存独立对话；`POST /api/agents/:id/conversations/:conversationId/remove` 删除并留下不含正文的标记。schemaVersion=4 保存请求包括完整 `messages`、`expectedVersion` 和幂等 `mutationId`；用户消息可带至多十项唯一 `attachments:[{id}]`，不保存文件正文或图片数据。无附件的旧版本 3 请求保持兼容，下次成功保存升级为 4；旧客户端不能覆盖已有附件的记录。版本冲突或已删除返回 HTTP 409 及对应原因。旧浏览器迁移使用 `importOnly: true` 只补缺失记录；旧 `/conversation` 接口保留兼容。

材料接口：`POST /api/agents/:id/attachments?name=<编码文件名>&mimeType=<类型提示>` 接收原文件字节流，服务端核对扩展名及内容类型；`GET /api/agents/:id/attachments` 列出当前 Agent 材料，`GET /api/agents/:id/attachments/:materialId` 读取说明。对应的 `/raw` 返回私有原件，`download=1` 用于下载；`/preview?offset=N` 分页读取提取文本；`/image?page=1` 返回上传图片或 PDF/TIFF 指定页的 PNG，`imageId` 可用于选择文档内嵌图片。材料状态为 uploaded、ready、needs_vision、failed；上传后按需解析，失败保留实际状态。模型工具为 `list_materials`、`read_material`、`read_material_image`，只接受当前 Agent 的材料 ID。材料上传和预览不启用工作 Agent 联网搜索。

## 需求记录与问题排查

主对话自动保存需求草稿、澄清消息和实际失败状态。遇到重复追问或连接报错时，可先保留当前输入，刷新查看已保存的对话，再重试本轮；失败或取消不会把尚未完成的草稿当作成功结果。需求面板可导出当前需求 JSON，文件包含用户描述，分享前请自行检查。

旧独立需求页面的内存诊断导出不再作为主入口。开发排查可读取 `GET /api/main/conversations/:id` 的消息状态和安全诊断类别；接口不返回 API Key 或模型服务的原始错误正文。

## 管理已有本机项目

点击左侧“管理项目”，项目列表常驻工作区左侧，右侧默认显示项目助手。选择项目后右侧展示详情，点击“项目助手”回到原对话；“问问助手”会将当前项目的名称与路径关联到下一条消息，可以在输入框上方取消关联。切换时保留对话草稿和未提交的启动配置。右上角“添加项目”打开文件夹选择器，也可手动粘贴路径；名称和用途为折叠的可选项。点击“添加并自动配置”后显示 PI 的检查进度，完成后选中新项目。项目列表和启动配置自动保存在本机 `.neuma/projects.json`，重启后恢复；项目聊天只放在本轮页面与服务器内存中，刷新或开启新对话会使用新的 Pi 会话。闲置 30 分钟的会话会释放；同时最多保留 12 份会话。

导航地址为 `#chat`、`#projects/list`、`#projects/assistant`、`#projects/add`、`#agents` 和 `#settings`。旧的 `#chat/projects`、`#manage/projects`、`#manage/agents`、`#add` 与 `#chat/requirements` 链接会转到对应的新位置。

发送后，用户消息立即进入对话并清空输入框。项目助手先显示“正在思考…”，随后随模型响应逐段显示文本；调用工具时展示实际的查看、登记、启动或停止状态，不展示模型思考原文或工具参数。回复期间可先写下一条草稿，右下角方形按钮可停止回复。停止或断线后保留已收到的文本，已执行的项目操作不会回滚；失败不自动重试，可重新编辑原消息再发送。主 Agent 同样立即显示用户消息，并根据正在处理的需求或群任务展示进度；需求澄清完成后统一呈现正式摘要与追问，未完成的需求轮次不覆盖上一份成功草稿。

添加只关联项目原位置，不复制或修改源码。表单添加与对话提供路径共用自动配置流程：PI 读取项目说明、依赖清单和必要入口，识别 Node、Python、启动脚本、静态网页或 macOS 应用，提交结构化启动方案。新项目检查期间只暂存在内存，不写入项目列表或记录文件；服务端核对方案后，配置成功才保存并显示项目，启用“打开项目”。入口不明、模型未配置、检查失败或取消时，新项目不登记；失败会显示脱敏后的具体原因，表单保留路径和名称，可点击“重试添加”。对话添加失败也结束本轮，不报告已登记或自动重复添加。只是添加不会执行代码。已有项目仍可重新识别，失败时保留原登记；重复添加已配置项目不会覆盖已有配置。自定义设置留在折叠的“高级配置”内。

点击“打开项目”或让 PI 启动项目后，后台在页面就绪时自动交给系统浏览器打开。详情页不嵌入 iframe，也不要求用户寻找页面链接；已运行的项目再次点击会直接打开现有页面，不重复启动进程。状态轮询不会重复弹窗。浏览器打开失败保留运行状态，仍可使用同一个按钮重试。

“运行与端口”提供按需刷新的本机快照：在“项目运行”里筛选运行中、未发现运行、无法确认的已登记项目；在“端口占用”里按端口号、进程或项目名称搜索。也可以直接问项目助手“哪些项目还没开”“3000 端口被谁占用了”。项目运行查询结合 NEUMA 托管进程和可见进程的工作目录，区分 NEUMA 启动与外部运行；仅端口号相同不算项目归属证据。没有关联到登记项目的监听进程仍会显示在端口列表。

本机查询只读取进程名、PID、工作目录及 TCP 监听信息，不读取进程命令参数或环境变量，不启动或关闭进程。Mac 使用 `lsof`、`ps`；Linux 使用有时间与读取上限的 `/proc`；Windows 使用随包原生程序查询系统进程与 TCP 监听。缺少辅助程序或权限不足时显示检查缺口，不把失败当作未运行。端口列表仅覆盖当前权限可见的 TCP 监听，不含 UDP 或全部网络连接；未发现监听不保证端口一定可用。进程从其他目录运行或通过容器启动时可能无法关联，因此“未发现运行”表示本次没有找到证据。运行概览不需要模型；通过助手查询时，相应项目状态、端口和进程名会作为工具结果提供给已配置的模型。

`GET /api/projects/runtime` 返回查询时间、项目状态分组、监听端口及关联项目、检查提示；关闭概览会取消尚未结束的查询。

静态网页使用独立本机端口提供预览，拒绝隐藏文件和越界符号链接。Node/Python 等项目按已保存的程序和参数启动，不通过 Shell 解释参数，不自动安装依赖。自动配置支持现有包管理器脚本、Node 文件、Python 文件及 Streamlit/Uvicorn/Flask 入口；可使用项目已有的 Python 虚拟环境。需要相应运行环境和依赖已就绪；识别并保存配置不代表代码已运行或页面已验证。程序的标准输出只用于提取本机页面地址，不回传整段日志；预览地址也可以在高级配置手动填写，仅支持本机 HTTP 地址。页面通过一次成功访问验证后显示。只有进程存活而没有页面时会说明入口未验证；脚本可能运行后直接结束。macOS 桌面应用在自身窗口打开，目前不能管理其窗口和关闭生命周期。

项目列表每项右侧都有“删除”，详情页也有“删除项目”。点击后确认具体项目和删除范围；只移除 NEUMA 的登记，保留电脑上的项目文件。删除会结束该项目正在进行的检查，并停止由 NEUMA 启动的进程，不停止外部启动的进程。也可以对项目助手明确说“删除某某项目”；助手先查列表确定目标，重名或指代不清时先询问。删除当前项目后回到项目助手，保留对话和草稿。

已有 Shell 启动脚本支持 `.sh/.bash/.zsh/.command`，由 PI 阅读后保存实际解释器、脚本和参数，不使用 `bash -c` 拼接命令。会启动后台服务后退出的脚本，还需保存项目自身的停止脚本和全部服务健康地址。启动脚本成功退出且服务全部就绪后才打开页面；启动脚本仍在处理时持续等待，可主动停止。停止通过原项目脚本完成，失败时保留可重试的运行记录。检查到完整服务已经在外部运行时只打开页面，不取得停止权限；部分端口已占用时提示处理占用，不接管未知进程。添加阶段只阅读和配置，不执行任何项目脚本。

添加失败现在显示具体原因，并单独写入本机 `.neuma/project-add-failures.json`，不写入项目列表。记录包含时间、项目名称/路径、失败阶段、脱敏原因和重试次数，不保存源码、模型原始响应或密钥；保留最近 50 条。可问项目助手“上次添加失败是什么原因”，或查询 `GET /api/projects/failures`。旧版未保存的失败无法补回。记录保存失败会明确说明，不掩盖原来的添加错误。

“停止”只停止由 NEUMA 启动并跟踪的进程或预览服务。关闭 NEUMA 服务时会停止受管理的项目。项目路径移动后需要重新登记。当前托管运行状态不写入磁盘，重启后按实际情况重新启动。

Pi 复用 `NEUMA_LLM_CHAT_URL`、`NEUMA_LLM_MODEL`、`NEUMA_LLM_API_KEY`；接口必须以 `/chat/completions` 结尾，并支持流式回复和工具调用。SDK 不自动加载电脑或项目里的 Pi 扩展、技能、指令和模型配置；不写入 Pi 的全局凭据或聊天文件，也不启用分析、安装遥测、模型目录网络更新或缓存预热。必要的对话、项目名称、用途、路径、类型及状态，以及自动检查读取的有限项目说明、依赖清单和入口片段，会发送给已配置的模型。读取工具限制在所选目录内，跳过隐藏文件、凭据文件、依赖目录和二进制文件，并隐藏常见凭据赋值；不读取 `.env` 或把 NEUMA 的模型密钥传给项目子进程。模型费用以服务商账单为准，SDK 内部占位费用不代表真实价格。

项目对话开放登记、列出、检查配置、启动、停止、删除登记、运行概览、端口查询和失败记录九个工具。独立的 PI 检查会话只开放目录列表、文本读取和提交启动方案三个工具，不共享对话历史，不开放任意 Shell、源码修改和源码删除。这是工具范围限制，不是项目代码的操作系统沙箱：用户点击启动的项目代码仍使用本地账户可用权限。尚未实现任意桌面按钮操作、跨设备管理，以及自动调用所有小应用内部功能。

项目助手和 PI 项目检查不设思考或执行时限，不会满 5 分钟自动暂停，也没有模型轮数、工具调用次数或累计文件读取额度限制；大目录和长文件按 `nextOffset` 分批继续读取。PI 专用连接关闭流式响应的空闲超时，模型正在处理但暂时没有文字输出时继续等待。用户主动停止或页面连接断开时仍可取消；旧版已暂停的项目可以重新发起检查。

只有可恢复的模型 API 故障（例如连接中断、限流、服务端暂时不可用）由 PI 最多重试 5 次，即首次请求加 5 次重连，界面显示当前次数。底层 HTTP 客户端不额外重试；重连期间保留会话和已完成的工具结果。重试耗尽后结束本轮，不再自动重新检查项目或通过上下文压缩额外请求模型。无效凭据等不可恢复错误直接提示检查连接。项目查询、读取文件和正常思考不受这个重试计数限制。

接口：`GET /api/projects` 查询已登记项目及进行中的添加数量 `pendingAdditions`；`POST /api/projects/pick-folder` 接收 `{}` 选择文件夹；`POST /api/projects` 接收 `{ "path": "完整路径" }` 并自动配置；`POST /api/projects/:id/inspect` 接收 `{}` 重新识别。这两个检查接口支持 `Accept: application/x-ndjson`，成功返回 `status` 和 `done.result.project`，失败返回 `error`；断线取消检查，未成功的新项目不保存，已有项目保留登记。`POST /api/projects/:id/configure` 保留手动设置，接收 `{ "command": "npm", "args": ["run", "dev"], "url": "", "allowLaunch": true }`；同一路径的 `start`、`stop` 接收 `{}`，`remove` 接收 `{ "confirm": true }`。`POST /api/projects/turn` 接收 `{ "message": "...", "sessionId": "浏览器生成的唯一标识" }`；添加 `Accept: application/x-ndjson` 后逐行返回 `status`、`text-start`、`text-delta` 和最终 `done`（含 `result`）或安全的 `error` 事件，未指定时仍返回完整 JSON。流意外断开会取消对应会话。`POST /api/projects/cancel` 取消回复，已执行操作会保留。接口拒绝外部 Origin、非本机 Host 和跨站请求；项目变更要求 JSON 请求。

## 管理本机 Skills

点击左侧“Skill 管理”，搜索本机已有技能并查看来源、路径、`SKILL.md` 正文和配套文件清单。首次进入时扫描通用、Codex、Claude、Pi 用户目录及插件缓存；已登记项目中的标准技能目录也会纳入。其他位置通过“扫描目录”添加，支持系统窗口或手填路径。“重新扫描”更新当前结果，不进行全盘搜索。同名技能的不同副本分别显示，共享目录的入口合并展示；异常格式和失效链接会标明原因。插件缓存表示本机存在该副本，不能据此判断插件是否正在启用。

普通用户目录中的技能可以直接编辑原 `SKILL.md`；脚本、参考资料等附带文件只显示清单。保存前检查格式，保留自定义字段和正文。编辑共享技能会影响其他使用同一文件的工具，详情中会显示已发现入口。原文件在编辑期间被外部修改时拒绝覆盖，当前草稿保留，可以查看磁盘版本并重新编辑。离开管理页保留本次编辑；刷新或关闭网页前请保存。系统内置与插件缓存只读，添加自选目录或通过软链接访问仍不能改写这些文件。

“导入”从本地技能文件夹复制整个目录，不移动原件。来源根目录须有 `SKILL.md`；每次明确选择通用、Codex、Claude、Pi 或项目目标目录，预览目标路径及包含的子技能。目标目录已存在时不覆盖、不合并，可以更改本次导入目录名称后重新预览。导入不会执行附带脚本，不提供联网安装。

“移至回收站”移动整个技能目录，确认前显示将一同移走的子技能以及受影响的共享入口。叶级软链接可以“移除此入口”，只移走链接，保留实际技能。回收站记录在当前 NEUMA 数据目录的 `skills/` 下管理，跨盘来源使用同盘隐藏回收区；没有自动永久清理。点击回收站的“恢复”放回原位置，原位置已有文件时拒绝覆盖并保留回收记录。

此页面是独立的本机文件管理能力，不需要模型连接。NEUMA 的需求、架构、研发、项目助手和工作 Agent 都不加载这些技能，不增加管理工具或文件权限；技能内容不会发送给模型，也不会加载扩展或安装依赖。其他工具何时重新读取已编辑的技能，由该工具自身决定。

接口：`GET /api/skills`、`POST /api/skills/scan` 查询与重新扫描；`GET /api/skills/:id` 读取详情，`POST /api/skills/:id/save` 接收 `{content,revision}` 保存；`GET/POST /api/skills/sources` 查询或添加目录，`POST /api/skills/sources/:id/remove` 移除自选扫描目录（保留文件）；`POST /api/skills/pick-folder` 接收 `{purpose:"source"}` 或 `{purpose:"import"}` 选择文件夹。`POST /api/skills/import/preview` 接收 `{path,targetId,name?}` 预览，`POST /api/skills/import` 额外携带返回的 `revision` 执行复制。`POST /api/skills/:id/trash/preview` 预览回收影响，`POST /api/skills/:id/trash` 接收 `{confirm:true,revision,action,locationId?}` 回收，`action` 为 `skill` 或 `link`。`GET /api/skills/trash` 查询回收站，`POST /api/skills/trash/:id/restore` 恢复。内容或确认范围已变化时返回 HTTP 409 和 `SKILL_CONFLICT`，不自动覆盖原文件。

## 判断方式

兼容模型更新同一份需求草稿，记录目标、场景、输入、核心任务、输出、成功标准、边界和建议调用场景，并区分用户明确说明、直接推导、系统暂定与未明确。配置 Jev 且本轮用户回答匹配到具体需求项时，Jev 只对该项辅助评分；未匹配到回答点时不调用，是否继续追问仍由需求模型和规则判断。代码确保目标、场景、输入、核心任务、输出、成功标准和对外动作边界不能凭猜测标为完成。信息足够且可行性与证据检查允许时，页面显示需求确认说明，等待用户确认；确认并保存成功后自动进入正式架构设计与独立评估，通过后生成轻量执行定义，或继续完成代码研发与验收；尚未具备的连接和运行能力明确保留下一步。Jev 失败时可按草稿继续。当前 Jev 阈值只是本地试验参数，中文效果尚未经过产品验收评测。

确认问题要求明确回复“确认”或直接说明修改内容。已展示确认问题后的明确同意不会重新提取草稿或再次调用 Jev，但仍受服务端当前的可行性与证据校验约束。确认通过且需求保存成功后，浏览器自动打开同一智能体并发起制作；保存失败不会触发构建。旧版双重问句后的单字“没有”会先澄清含义。用户暂时无法提出额外完成标准时，不会重复追问同一个可选标准。

字段填满不等于需求已澄清。输入来源、核心处理方式和输出必须来自用户说明或对已展示的具体建议的接受；系统推测不能直接进入最终确认。推测出的完成标准、有效的模型追问和阻塞性未解决事项也会阻止提前确认。宽泛愿望先通过一个容易回答的问题了解主要困难，再澄清处理重点和结果；信息充分时无需固定轮数的追问。用户否定方案时提供纠正方向选项，可只回编号，随后继续针对性澄清。

若模型配置不全，页面会显示连接状态；发送消息会返回明确错误。密钥仅填写在本机“设置”的 API Key 字段或 `.env` 中，不要放入聊天内容或提交到版本库。

接口：`GET /api/health` 返回连接配置状态。主入口使用 `POST /api/main/conversations/:id/operations` 提交 `{mutationId,message,attachmentIds?}`；接受回执包含 `operation` 与快照。`GET /api/main/conversations/:id/operations/:operationId?after=<cursor>` 续看，`POST` 同路径 `/cancel` 携带 `{generation}` 精确停止。相同请求编号不能更换内容；重复查看不执行任务。兼容 `POST /api/main/conversations/:id/messages` 仍在同一会话中路由普通对话、需求和群任务，保留原流式等待与断开取消语义；`POST /api/main/conversations/:id/requirements` 接收 `{mutationId, agentId?}`，激活新建或指定 Agent 的迭代草稿。主回复流中的 `context` 事件告知界面展示需求或群任务，完成响应携带持久化会话及当前上下文。独立的 `POST /api/requirements/turn` 继续保留，接收 `{ "message": "...", "draft": null, "lastQuestion": "", "userMessages": [] }`，返回更新草稿、`needs_input` 或 `ready`、至多一个追问、摘要、Jev 参与状态及诊断摘要。失败响应只返回安全的错误类别、HTTP 状态和重试次数，不返回密钥或接口原始响应。

制作与研发的后台入口：`POST /api/agents/:id/operations`，构建传 `{kind:"build",mutationId,name,draft,architectureRepair?}`，研发传 `{kind:"development",mutationId,resume}`。使用 `GET /api/agents/:id/operations/:operationId?after=<cursor>` 查看，`POST` 同路径 `/cancel` 传 `{generation}` 停止。智能体详情的 `operationReference` 可定位正在执行的任务。游标变化时按返回的完整快照替换显示，不重复拼接正文。旧 `/api/agents/build`、`/api/agents/:id/development/stream` 继续兼容。
